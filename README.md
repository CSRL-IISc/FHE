# CKKS → TFHE Scheme Switching

Step-by-step guide to converting a CKKS ciphertext into TFHE LWE ciphertexts so you can
evaluate non-polynomial functions (sign, ReLU, max, comparison, sigmoid, modular reduction)
via programmable bootstrapping.

Worked with toy parameters **N = 8, Q = 256** for illustration; production notes throughout.

> **Reference implementations of this idea:**
> - **CHIMERA** — Boura, Gama, Georgieva, Jetchev (2018/2020). Common-ring framework
>   bridging TFHE / BFV / HEAAN.
> - **PEGASUS** — Lu, Huang, Hong, Ma, Qian (IEEE S&P 2021). The CKKS ↔ FHEW/TFHE
>   pipeline described here, including repacking back to CKKS.
> - **CDKS repacking** — Chen, Dai, Kim, Song (2021). LWEs-to-RLWE packing.
> - Available in **OpenFHE** (`SchemeSwitching` / `EvalCKKStoFHEW`) and **Lattigo**.

## 0. Why switch at all

| | CKKS | TFHE |
|---|---|---|
| Ciphertext | RLWE, ring dim N ~ 2^16 | LWE, dim n ~ 630–900 |
| Data layout | N/2 complex **slots** | one message per ciphertext |
| Plaintext | fixed-point real, scale Delta | discretized torus, message in MSBs |
| Precision | 20–40 bits | 2–6 bits |
| Cheap | SIMD add / mult, polynomials | arbitrary function via LUT |
| Expensive | sign, comparison, ReLU, max | vector arithmetic, high precision |
| Bootstrap | rare, amortized over slots | every gate, ~10–100 ms each |

**Use case:** an encrypted neural network. Do the matrix multiplies in CKKS (SIMD, cheap),
switch to TFHE for the ReLU / argmax (LUT, exact), switch back for the next layer.

## 1. Pipeline overview

```
  CKKS RLWE ciphertext, slot layout, modulus Q_L
        |
        |  (1) Slots-to-Coefficients  -- homomorphic decoding linear map
        v
  CKKS RLWE ciphertext, COEFFICIENT layout
        |
        |  (2) Rescale / modulus switch down to small Q
        v
        |  (3) Sample extraction (LWE extraction)   <-- FREE, no crypto
        v
  N LWE ciphertexts, dimension N, under key s_coeff
        |
        |  (4) LWE key switching:  dim N -> dim n,  s_coeff -> s_TFHE
        v
  LWE ciphertexts, dimension n, TFHE key
        |
        |  (5) Modulus switch to 2N_tfhe  (blind-rotation domain)
        v
  TFHE LWE ciphertext
        |
        |  (6) Programmable bootstrapping: evaluate any LUT
        v
  Refreshed TFHE LWE ciphertext of f(m)
        |
        |  (7) OPTIONAL: repack LWEs -> RLWE, then Coeffs-to-Slots
        v
  CKKS ciphertext again
```

Only steps (1), (4), (6), (7) cost real computation. Step (3) is pure index arithmetic.

## 2. Step 1 — Slots-to-Coefficients (StC)

### Why it is needed

Sample extraction pulls out **coefficients** of the plaintext polynomial `m(X)`. But your
data lives in the **slots** — i.e. in `sigma(m)`, the evaluations at the roots of `X^N+1`.
These are different things:

```
m(X) = 16 + 15X + 11X^2 + 6X^3 + 0X^4 - 6X^5 - 11X^6 - 15X^7     <- coefficients
sigma(m)/Delta = (2.0, 0.0, 0.0, 0.0)                            <- slots
```

Extracting coefficient 3 would give you `6`, which is *not* any slot value. So first you
must homomorphically apply the CKKS **decoding** map, moving slot values into coefficient
positions.

### How it works

Decoding is the linear map `sigma`, i.e. multiplication by the DFT matrix `U`. Homomorphic
evaluation of a linear map on slots is done with **rotations plus plaintext multiplications**:

```
StC(ct) = sum_i  rot_i( ct ) * diag_i(U)
```

- Decompose `U` into its `N/2` diagonals; each diagonal is a plaintext vector.
- Use the **baby-step giant-step (BSGS)** decomposition to reduce `O(N)` rotations to
  `O(sqrt(N))`.
- Split the DFT into `log(N)` sparse radix-2 stages (the "FFT-like" StC) to reduce
  multiplicative depth from 1 big level to several cheap ones — this is the standard
  optimization from CKKS bootstrapping.

### Cost

- Depth: 1 level (naive) or `log N` cheap levels (FFT-style).
- Keys required: **rotation (Galois) keys** for the relevant rotation amounts.
- This is by far the most expensive step in the whole switch.

### Note

For N = 8, the rotation group is generated by `X -> X^5`: exponents `5^0,5^1,5^2,5^3 mod 16`
= `1, 5, 9, 13`, giving a 4-cycle over the four slots.

**Shortcut:** if you never needed slot packing in the first place — i.e. you encoded your
data directly into coefficients — you can skip StC entirely. PEGASUS calls this the
"coefficient encoding" path. Worth designing for if switching is frequent.

## 3. Step 2 — Rescale / modulus switch

TFHE operates on a small modulus (typically `2^32` or `2^64` interpreted as a discretized
torus). CKKS ciphertexts live at a large `Q_L` (hundreds of bits).

1. **Rescale** down the modulus chain to remove accumulated scale factors.
2. **Modulus switch** `Q -> q`: multiply every ciphertext coefficient by `q/Q` and round.

```
c' = round( c * q / Q )   mod q
```

Modulus switching adds **rounding noise** proportional to `||s||`, so leave headroom.

### Toy demonstration of what goes wrong at small parameters

```
coefficient value at Q=256 :   9
after switch to q=32       :   0        (expected ~1.12)
```

At Q = 256 there is no headroom at all, so the value is annihilated. This is exactly why
scheme switching requires a **large starting modulus** — you need enough bits that
`q/Q` rounding stays below your precision floor.

## 4. Step 3 — Sample extraction (the key step)

### Derivation

A CKKS/RLWE ciphertext is `(c0, c1)` with

```
c0 + c1 * s = m + noise    in  R_Q = Z_Q[X]/(X^N + 1)
```

Write out coefficient `k` of the product `c1 * s` using the **negacyclic convolution** rule:

```
(c1 * s)_k  =  sum_{j=0}^{k} c1_{k-j} * s_j   -   sum_{j=k+1}^{N-1} c1_{N+k-j} * s_j
                                              ^
                                              |  the minus sign is X^N = -1
```

Therefore:

```
m_k  =  c0_k  +  < a', s >        where s = (s_0, ..., s_{N-1}) as a plain vector
```

with

```
a'_j  =    c1[k - j]        for j <= k
a'_j  =  - c1[N + k - j]    for j >  k
b'    =    c0[k]
```

**That is a valid LWE ciphertext** `(a', b')` of dimension `N` encrypting `m_k` under the
secret key `s` viewed as a coefficient vector.

### Properties

- **Zero cost.** No multiplications, no key material, no noise growth. Pure index shuffling
  with sign flips. It is literally a memory rearrangement.
- **Exact.** No approximation is introduced.
- Produces up to `N` independent LWE ciphertexts from one RLWE ciphertext (you usually only
  extract the ones you need).

### Reference implementation

```python
def extract(c0, c1, k, N, Q):
    """RLWE (c0,c1) -> LWE (a,b) encrypting coefficient k, under key s as a vector."""
    a = []
    for j in range(N):
        if j <= k:
            a.append( c1[k - j] % Q)
        else:
            a.append((-c1[N + k - j]) % Q)
    return a, c0[k]
```

### Verified on the toy ciphertext

```
s      = [0, 1, 0, 0, 1, 1, -1, -1]
c0     = [33, 126, 160, 55, 131, 211, 99, 204]
c1     = [126, 129, 20, 201, 24, 179, 70, 199]
RLWE decryption m' = [14, 14, 9, 9, -4, -9, -12, -16]

k=0: LWE dec =  14   RLWE coeff =  14   MATCH
k=1: LWE dec =  14   RLWE coeff =  14   MATCH
k=2: LWE dec =   9   RLWE coeff =   9   MATCH
k=3: LWE dec =   9   RLWE coeff =   9   MATCH
k=4: LWE dec =  -4   RLWE coeff =  -4   MATCH
k=5: LWE dec =  -9   RLWE coeff =  -9   MATCH
k=6: LWE dec = -12   RLWE coeff = -12   MATCH
k=7: LWE dec = -16   RLWE coeff = -16   MATCH
```

Every coefficient extracts exactly. LWE decryption is `b + <a, s> mod Q`.

## 5. Step 4 — LWE key switching

### The mismatch

After extraction the LWE ciphertexts have **dimension N** (e.g. 65536) and are encrypted
under the CKKS secret `s_coeff`. TFHE bootstrapping requires **dimension n** (e.g. 630–900)
under the TFHE key `s_TFHE`. Blind rotation cost is linear in `n`, so you cannot skip this.

### Key-switching key

Publish encryptions of the CKKS key bits under the TFHE key. For decomposition base `B`
and `d` levels:

```
KSK[i][v][j] = LWE_{s_TFHE}( v * B^j * s_coeff[i] )
    i = 0 .. N-1        (each CKKS key coefficient)
    j = 0 .. d-1        (decomposition level)
    v = 1 .. B-1        (or use gadget form)
```

Size is `O(N * d * n)` — this is typically the **largest key in the whole system**, often
gigabytes. Budget for it.

### Procedure

```
1. Gadget-decompose each a'_i into digits:   a'_i = sum_j  a_{i,j} * B^j
2. Start from the trivial LWE ciphertext (0, b')
3. Subtract the matching KSK entries:
       result = (0, b')  -  sum_i sum_j  a_{i,j} * KSK[i][j]
```

### Cost

- Noise grows additively; keep `B` small (e.g. 2^4) and `d` moderate to control it.
- Runtime `O(N * d)` LWE additions. Non-trivial but far cheaper than StC.

## 6. Step 5 — Modulus switch into the rotation domain

Blind rotation treats the ciphertext body as a **rotation index** into a polynomial of
degree `N_tfhe`. Rotation is mod `2*N_tfhe`, so switch the modulus again:

```
tilde_a_i = round( a_i * 2*N_tfhe / q )
tilde_b   = round( b   * 2*N_tfhe / q )
```

Now `tilde_b + <tilde_a, s>` is a small integer in `[0, 2*N_tfhe)` — the rotation amount.

**Message placement matters.** The message must sit in the **most significant bits** with:
- a **padding bit** at the very top (if using the standard negacyclic-safe PBS), and
- enough low bits reserved for noise.

```
  MSB                                              LSB
  [ pad | message (2-6 bits) | ------ noise ------ ]
```

---

## 7. Step 6 — Programmable bootstrapping (the payoff)

### Mechanism

1. **Test polynomial (LUT).** Build `v(X)` of degree `< N_tfhe` whose coefficients encode
   your desired function `f` sampled over the message space, laid out in "boxes"
   (each message value gets a contiguous run of coefficients, giving noise tolerance).
2. **Blind rotation.** Using RGSW bootstrapping keys `BSK_i = RGSW(s_i)`, homomorphically
   compute `X^{-(tilde_b + <tilde_a,s>)} * v(X)`. Each step is a CMux / external product.
3. **Sample extract** coefficient 0 of the result — the same free operation from step 3.
4. **Key switch** back down to dimension `n`.

Output: a fresh LWE ciphertext of `f(m)` with noise **independent of the input noise**.
This is what makes TFHE unbounded-depth.

### The negacyclic constraint

Because the ring is `Z[X]/(X^{N}+1)`, rotating by `N` negates:

```
rotate by  0 : constant term = +5
rotate by  2 : constant term = -5
rotate by  8 : constant term = -5
rotate by 10 : constant term = +5
```

(measured on the toy, N = 8, constant test polynomial)

So any directly-encodable LUT must satisfy

```
f(x + N) = -f(x)        "negacyclic function"
```

**Workarounds:**
- **Padding bit** — reserve the MSB as always-zero, restricting inputs to the first half
  of the rotation range. Costs one bit of message space. Standard approach.
- **No-padding PBS** — run a preliminary PBS to clear the top bit, then the real one.
  Costs 2x.
- **Odd functions** — `sign`, `sin`, and odd polynomials are already negacyclic. Free.

Notice this is the *same* `X^N = -1` rule that produced the sign flip in sample extraction
and in CKKS multiplication. One structural fact, three consequences.

### What you can now compute

```
sign(x), abs(x), ReLU, max(a,b) via sign, comparison, equality test,
sigmoid / tanh, modular reduction, arbitrary 6-bit lookup table,
digit extraction, rounding
```

All in one bootstrap each, exactly — no polynomial approximation, no depth cost.

## 8. Step 7 — Optional: switch back to CKKS

To return to SIMD-land:

1. **Repack** the `N` LWE ciphertexts into a single RLWE ciphertext.
   - CDKS ring-packing, or the field-trace / `LWEs-to-RLWE` method.
   - Requires packing keys; cost `O(N log N)` automorphisms.
2. **Coefficients-to-Slots (CtS)** — the inverse of step 1, another homomorphic linear map.
3. **Adjust the scale** to your target Delta and continue CKKS evaluation.

Round-trip cost is dominated by StC + CtS. Batch as much work as possible per switch.

## 9. Cost summary

| Step | Cost | Noise | Keys needed |
|---|---|---|---|
| 1. Slots-to-Coeffs | **high** — `O(sqrt N)` rotations, log N levels | moderate | rotation/Galois keys |
| 2. Mod switch | negligible | additive rounding | none |
| 3. Sample extract | **free** | none | none |
| 4. LWE key switch | `O(N*d)` additions | additive | KSK (**largest key**) |
| 5. Mod switch to 2N | negligible | additive rounding | none |
| 6. PBS | `O(n)` external products, ~10–100 ms | **resets noise** | RGSW bootstrap keys |
| 7. Repack + CtS | high | moderate | packing + rotation keys |

**PBS is per-ciphertext.** Switching a full CKKS ciphertext with 32768 slots means 32768
bootstraps. Extract only the values you actually need.

## 10. Practical checklist

- [ ] Budget modulus: you need enough `Q` left after StC to survive two modulus switches.
- [ ] Match precision: TFHE gives 2–6 bits. Confirm your CKKS values fit *after* rounding.
- [ ] CKKS noise becomes message error. Unlike BGV/BFV, CKKS noise is inside the message —
      make sure the gap between your noise floor and TFHE's message bits is real.
- [ ] Reserve the padding bit unless your LUT is genuinely odd.
- [ ] Consider coefficient encoding from the start to skip StC entirely.
- [ ] Amortize: batch many values per switch; the fixed StC/CtS cost dominates.
- [ ] Generate all key material up front — rotation keys, KSK, BSK. The KSK is often GBs.
- [ ] Security: both schemes must target the same lambda. Check the Lattice Estimator for
      the *pair* of parameter sets, not each in isolation.

## 11. Toy code — sample extraction

```python
import numpy as np, random
N, Q, DELTA = 8, 256, 32

def negacyclic_mul(a, b, q=Q):
    r = [0]*N
    for i in range(N):
        for j in range(N):
            if i + j < N: r[i+j] += a[i]*b[j]
            else:         r[i+j-N] -= a[i]*b[j]
    return [x % q for x in r]

def extract(c0, c1, k):
    """RLWE -> LWE for plaintext coefficient k."""
    a = [ c1[k-j] % Q if j <= k else (-c1[N+k-j]) % Q for j in range(N) ]
    return a, c0[k]

def lwe_decrypt(a, b, s, q=Q):
    d = (b + sum(ai*si for ai, si in zip(a, s))) % q
    return d - q if d > q//2 else d

def mod_switch(a, b, q_from, q_to):
    return ([round(x*q_to/q_from) % q_to for x in a],
             round(b*q_to/q_from) % q_to)
```
